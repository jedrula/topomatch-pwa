## Store Pipeline

### Entry Point
```javascript
setFrames(ascentId, frames, comparisonProblems, locationId)
```
- Component calls this after extracting frames (DOM work)
- Auto-creates job if it doesn't exist
- Starts autonomous pipeline immediately
- Component can unmount - pipeline continues in background

### Step 1: Pose Detection (0-20%)
- Uses YOLO pose detection on all frames
- Extracts keypoints: leftHand, rightHand, leftFoot, rightFoot
- Stores pose data in each frame
- Progress: 0-20%

### Step 2: Image Matching (20-40%)
- Uses SuperPoint + LightGlue neural network feature matching
- Compares video frames against all location images
- Finds best match by feature count
- Calculates homography matrix (video coords → image coords)
- Stores: `matchedImageId`, `homographyMatrix`
- Progress: 20-40%

### Step 3: Hold Loading (40-60%)
- Loads AI-detected holds (YOLO) from Firestore
- Loads manual holds from Firestore
- Only loads holds for the matched image
- Holds stay in image coordinate space (NO transformation yet)
- Stores: `holds` array
- Progress: 40-60%

### Step 4: Problem Scoring (60-90%)
- Transforms pose keypoints from video coords → image coords using homography
- Now poses and holds are in same coordinate space!
- Calls `calculateProblemScores()` utility
- Sorts problems by total score (highest first)
- Stores: `scores` array
- Progress: 60-90%

### Step 5: Firestore Update (90-100%)
- Updates ascent record with detected problemId (if score > 50%)
- Adds analysisMetadata with scores
- Does NOT touch video object (upload queue manages that)
- Progress: 90-100%
- Status: 'complete'

## Job Structure

```javascript
{
  id: string,              // crypto.randomUUID()
  ascentId: string,        // Pre-generated by component
  locationId: string,      // Passed from component
  videoFile: null,         // Not needed (component handles upload)
  comparisonProblems: [],  // Boulder problems with imageUrl
  
  status: 'queued' | 'detecting' | 'matching' | 'loading-holds' | 'scoring' | 'complete' | 'error',
  progress: 0-100,
  
  extractedFrames: [],     // Frames with imageData and poseData
  matchedImageId: null,    // Set by Step 2
  homographyMatrix: null,  // Set by Step 2 (transforms video→image coords)
  holds: [],               // Set by Step 3 (AI + manual holds)
  scores: null,            // Set by Step 4 (sorted by totalScore)
  
  error: null,
  createdAt: number,
  completedAt: number | null
}
```

## Exported API

```javascript
{
  // State
  jobs,                    // Reactive ref of all jobs
  
  // Computed
  activeJobs,             // Jobs not complete/error
  completedJobs,          // Jobs with status='complete'
  hasActiveJobs,          // Boolean
  getActiveJob,           // First active job
  
  // Actions
  setFrames(ascentId, frames, problems, locationId),  // Main entry point
  getJob(ascentId),       // Get job by ID
  cancelJob(ascentId),    // Cancel job
  clearAll(),             // Clear all jobs (testing)
}
```

## Key Features

### 1. Auto-Job Creation
- Component doesn't need to call `addJob()` first
- `setFrames()` creates job automatically if missing
- Simplifies component code

### 2. Background Processing
- All steps run asynchronously
- Component can unmount immediately after `setFrames()`
- Progress tracked in job.status and job.progress
- Errors captured in job.error

### 3. Coordinate Transformation
- Video coordinates ≠ Image coordinates
- Step 2 calculates homography matrix
- Step 4 transforms poses to image space
- Now poses match holds for accurate scoring!

### 4. Smart Hold Loading
- Only loads holds for the matched image (not all images)
- Combines AI-detected + manual holds
- Handles missing hold data gracefully

### 5. Firestore Integration
- Updates ascent with detected problemId
- Adds analysisMetadata with scores
- Respects video upload queue (doesn't touch video object)
